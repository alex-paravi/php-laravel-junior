## Требует отложенного повторения

### Ссылки в foreach: висячая ссылка

24 октября сначала был ответ [20, 40, 60], после разбора — верный [20, 40, 40]. После foreach ($numbers as &$number) переменная $number остаётся ссылкой на последний элемент; второй обычный foreach на последней итерации присваивает в этот элемент своё значение.

```php
$a = [1, 2, 3];
foreach ($a as &$v) { $v *= 10; }
foreach ($a as $v) { }
```

Упражнение: не запуская, назови итог, затем объясни, почему unset($v) сразу после первого цикла предотвращает эффект.

### clone: причина общего города

Задание — 4/5: итог верно назван Alex/Kazan и Ivan/Moscow в соответствующем варианте, но объяснение «вложенные объекты перезаписываются» неверно. Нужная фраза: clone создаёт новый верхний объект, но при shallow copy вложенный объект остаётся общим; меняется его свойство.

Упражнение: добавь \_\_clone() с $this->address = clone $this->address; и предскажи города оригинала и копии после изменения города только в копии.

### Closures: внешняя переменная не глобальная

Результаты 20 / 50 / 20 названы верно (4/5), но переменная из use была названа глобальной. Это разные механизмы. use ($rate) захватывает внешнюю лексическую переменную по значению; use (&$rate) — её же по ссылке; global $rate обращается к глобальной области.

Упражнение: сравни эти три варианта и для каждого скажи, когда фиксируется значение и откуда оно берётся.

### strict_types: исключение int → float

Базовая строгая типизация — 4.5/5, но задача на передачу int в параметр float при declare(strict_types=1) — 0/5. Верное правило: int разрешён для float даже в strict mode. Это безопасное расширение; обратный путь float → int не симметричен.

Упражнение: в строгом файле предскажи результат f(float $x): float с вызовом f(7), а затем g(int $x): int с вызовом g(7.2).

### Возврат float → int в weak mode

Задача — 3/5. В слабом режиме float мог неявно усечься до int, но такое преобразование с потерей точности deprecated в современных PHP. Не строить на этом код: выбирать корректный тип контракта или явное преобразование с осмысленным округлением.

Упражнение: объясни разницу между return 3.8 из функции с : int и return (int) 3.8. Во втором случае всё равно нужно решить: усечение или округление действительно нужно бизнес-логике?

## 26 октября — закрытые затруднения и новые опоры

### Повторение `strict_types`, `clone` и висячей ссылки — 5/5

Все три ранее неустойчивые темы воспроизведены верно. Их не нужно забывать: теперь достаточно коротких предсказаний без запуска. Точные формулировки такие: `int` допустим для `float`; shallow clone оставляет вложенный объект общим без явного `__clone()`; `unset($value)` после цикла по ссылке снимает привязку имени к последнему элементу.

### Самостоятельная сборка зависимостей

Затруднение было не в синтаксисе, а в последовательности: как создать объект и передать то, что названо интерфейсом. Решение: сначала создать `ConsoleLogger`, затем передать его в `UserService`. Интерфейс не инстанцируется — он проверяет, что объект поддерживает контракт.

```php
$logger = new ConsoleLogger();
$service = new UserService($logger);
```

Это ручная конструкторная DI. После разбора цепочка была собрана и применена корректно.

### Лишнее присваивание результата `void`-метода

Строка `$result = $service->createUser('Alex');` не ломает программу, но вводит в заблуждение: `createUser(): void` не возвращает ни пользователя, ни статус. Переменная получает `null` и не нужна.

```php
$service->createUser('Alex');
```

`echo` внутри `ConsoleLogger::log()` показывает текст, но не превращает его в результат `createUser()`: вывод и возвращаемое значение — разные механизмы.

## Требует короткого контрольного повторения

1. Нарисовать цепочку `LoggerInterface` → `ConsoleLogger` → `UserService`, отметив контракт, `new` и передачу объекта.
2. Объяснить одной фразой: `new` создаёт конкретный объект сейчас; Laravel Service Container собирает зависимости по правилам приложения.
3. Написать две версии `createUser`: одну с `: void` и логированием, другую с `: User` и осмысленным `return`.
